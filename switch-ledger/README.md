# Cart Log · Switch 花费与 eShop 余额

一个记录 Switch 相关花费的单页应用：卡带、配件、点卡、eShop 数字版游戏都能记，并且按区服维护 eShop 余额。

采用「现金支出」口径：点卡充值和信用卡直购算现金支出；用 eShop 余额买游戏只扣余额，不重复计现金。这样不会因为「先买点卡、再用余额买游戏」重复花钱。

纯静态、无后端、无第三方依赖、无需联网，数据保存在当前浏览器本地。支持安装到桌面和离线使用。

版本与改动记录见 [CHANGELOG.md](CHANGELOG.md)（当前 1.1.0）。

## 四页

- **概览 `#overview`（默认）**：净花费 Hero、eShop 钱包、四联统计卡和「查看全部清单」入口。
- **清单 `#ledger`**：全宽搜索、排序、类型 chips、实体状态 chips、记录列表；当前不显示图表或备份。
- **统计 `#stats`**：近六个月现金支出、平台分布、分类占比（卡带/配件/点卡/eShop）。余额购游戏不计现金。
- **设置 `#settings`**：外观、平台/配件类型/区服管理、数据与备份、关于。

桌面宽屏（≥960px）使用顶部四 tab；窄屏（<960px）使用底部四入口导航，并预留 safe-area 与正文底部空间。视图切换使用 hash，支持浏览器后退、刷新保持当前页。

## 功能

- 记录类型：卡带 / 配件 / 点卡 / eShop 游戏
- 卡带和配件可标记「已出二手」，记录售出价格、日期和平台，自动折算净成本
- 点卡不记录使用状态：填写面值、区服和实际人民币购入价后，面值自动充入对应 eShop 余额
- eShop 游戏区分「余额支付」和「直购」：
  - 余额支付：扣除对应区服余额，不重复计入现金支出
  - 直购：同时记录 eShop 原币标价和实际支付人民币
- 多区服余额：默认港服 / 日服 / 美服 / 欧服 / 国服 / 其他；每个区服使用自己的币种，互不混算
- 「其他」区服保留自选币种；内置非「其他」区服与自定义区服锁定各自币种
- 自定义区服支持任意三位大写币种（如 TWD / KRW / AUD）；Intl 可识别的币种使用其小数位，不支持的显示为 `CODE 1,234.00`（2 位）
- 点击钱包卡查看该区服明细：全部 / 点卡 / 游戏，直购游戏标注「不扣余额」；卡内小按钮用于调整余额
- eShop 钱包支持手动调整余额；余额购游戏超支会先二次确认
- 设置页管理平台、配件类型、区服：内置项可隐藏/恢复，自定义项可新增、改名、停用/恢复，未使用项可删除
- 改名会二确认并级联旧记录；区服改名同时更新记录和余额调整
- 已使用项停用后不出现在新记录表单，但旧记录保留原值
- 主题：暖白（默认）/ 深色 / 跟随系统；尽早应用避免刷新闪白
- 首页统计的展开/收起状态会记住，手动收起后刷新仍保持收起
- 桌面端记账表单为 520px 右侧抽屉，手机端为全屏 sheet
- 搜索、排序、编辑、删除、跨标签页自动同步
- JSON 完整备份与恢复、CSV 表格导出
- PWA：可安装到桌面、离线可打开、支持快捷方式（记一笔 / 记点卡 / 记 eShop / 查看已出）；安装版在 manifest 中锁定竖屏
- 响应式布局，适配 320px 起的手机、平板和桌面；资源全部本地化

## 花费与余额规则

- **现金支出** = 卡带/配件购入价 + 点卡实际购入价 + eShop 直购实付人民币
- **二手回血** = 已出二手的卡带/配件售出价
- **净花费** = 现金支出 − 二手回血
- **eShop 余额** = 点卡面值合计 − 余额购游戏扣减 + 手动调整
- eShop 余额是预付资产，不计入「二手回血」，也不会被重复算成现金支出
- 点卡面值按原币进入对应区服钱包，例如 500 HKD 点卡进入港服 HKD 钱包
- 直购游戏不扣余额；余额购游戏不增加现金支出
- 不同区服、不同币种分别显示，不做自动汇率换算
- 余额购游戏若会使钱包变负，保存前会二次确认；取消可先补记点卡或调整余额
- 分类占比中，卡带/配件/点卡/eShop 均按现金支出汇总；eShop 余额游戏计 0

> 点卡购买后默认视为已充值到对应余额。若只是买了还没兑换，可先用「调整余额」做负数修正，兑换时再补正。

## 设置

### 外观

选择「暖白 / 深色 / 跟随系统」。深色覆盖页面背景、卡片、Hero、钱包、图表、输入、弹窗和底部导航，并保留 Switch 红。主题保存在本机，刷新时由头部脚本提前应用。

### 选项管理

- 管理区按「平台 / 配件类型 / 区服」三段折叠，默认全部收起，点击展开当前分类；桌面端选项双列排列，手机单列
- 内置平台、配件类型、区服可隐藏或恢复，不可删除；「其他」平台、配件类型「其他配件」和区服「其他」固定保留。
- 自定义项可以新增、改名、停用/恢复；已使用的自定义项不能删除，只能停用。
- 显示「使用中 N 条」；平台统计包含购入平台和出售平台。
- 改名需要确认；确认后会级联更新旧记录。区服改名同时更新记录与余额调整。
- 自定义区服新增时填写名称和三位大写币种；创建后币种锁定，改名不改币种。
- 恢复默认设置只重置主题与选项，不删除记录。

### 数据与备份

- **导出完整备份**：JSON v5，包含记录、余额调整、设置、主题和自定义选项。
- **导入备份**：与现有账本合并，只合并记录和余额调整，不覆盖当前设置。
- **覆盖恢复全部数据**：二次确认后用备份替换记录、余额调整和设置。
- **清空账本**：只删除记录与余额调整，保留当前主题和选项。
- **CSV**：只导出记录，用于表格查看。
- 旧版本备份（v1–v4）可导入；缺失 settings 时使用默认设置。比当前版本更新的备份会被拒绝。

## 本地预览

在项目目录中启动任意静态服务器（示例使用 Python）：

```bash
cd switch-ledger
python3 -m http.server 8090
```

打开 <http://localhost:8090/>。四个视图可直接访问：

- 概览：<http://localhost:8090/#overview>
- 清单：<http://localhost:8090/#ledger>
- 统计：<http://localhost:8090/#stats>
- 设置：<http://localhost:8090/#settings>

也可以运行附带的 `./serve.sh`，默认监听 `0.0.0.0:8090`。

> 直接双击 `index.html`（`file://`）可以查看页面，但浏览器不会注册 Service Worker，不能安装为 PWA。安装和离线能力必须通过 `localhost` 或 HTTPS 访问。

## 安装到桌面

### Android / Chrome / Edge

1. 通过 `localhost` 或 HTTPS 打开页面。
2. 点地址栏右侧的安装图标，或浏览器菜单里的「安装应用 / 添加到主屏幕」。
3. 安装后从桌面图标打开。

### iPhone / iPad

1. 用 Safari 打开页面。
2. 点底部工具栏的「分享」。
3. 选择「添加到主屏幕」。

iOS 不会自动弹出安装提示，按上述步骤添加后会以全屏方式打开。

> Android 安装版的方向由 `manifest.webmanifest` 的 `"orientation": "portrait"` 决定，不跟随系统旋转锁定。已安装的旧版本如果仍会旋转，通常需要重新安装 PWA 才会应用新的方向设置。**重装前请先在设置中导出 JSON 备份**，卸载 PWA 可能清除本机账本数据；普通浏览器标签页仍会跟随系统方向。

## 数据说明

- 记录保存在浏览器 `localStorage`，键名：`cartlog.switch.v1`
- 当前存储结构：`{ app, version: 5, records, adjustments, settings }`
- `settings` 包含 `{ theme, platforms, accessoryTypes, regions }`
- 不会上传到任何服务器；清理浏览器数据、卸载浏览器、更换设备或使用无痕模式都可能导致数据丢失
- 建议定期在「设置 → 数据与备份」导出 JSON
- 相同 `id` 的记录合并时保留更新时间较新的版本；余额调整按 `id` 去重
- 旧版本备份自动迁移；旧点卡会尽量从原「面值 / 区服」文本中解析面值与币种

## 部署

整个目录就是可部署产物，上传到任意支持 HTTPS 的静态托管即可：

- Netlify Drop / Vercel / Cloudflare Pages
- GitHub Pages
- 自建 Nginx / Caddy 静态站点

所有路径都是相对路径，可以部署在域名根目录，也可以放在子目录（例如 `/switch-ledger/`）。

本项目已随 [Zps165/Zps165.github.io](https://github.com/Zps165/Zps165.github.io) 一起发布，位于仓库的 `switch-ledger/` 子目录（`master` 分支自动构建）：

- 直接访问：<https://zps165.github.io/switch-ledger/>
- 站点入口：<https://zps165.github.io/>

更新流程：把文件同步到仓库的 `switch-ledger/` 目录 → 提交并 `git push origin master`。Service Worker 是网络优先的，页面文件改完刷新即生效，不用再改版本号；只有想一次性丢掉旧缓存时才需动 `sw.js` 的 `CACHE`。

### 更新版本

`sw.js` 使用**网络优先**策略：先请求网络，成功就返回最新内容并写回缓存，只有离线或请求失败时才回退到缓存；请求还带 `cache: 'no-cache'`，绕过浏览器 HTTP 缓存。

所以修改 `index.html` / `styles.css` / `app.js` 后**不需要改版本号**，用户刷新就能拿到新文件：

```js
const CACHE = 'cartlog-v19'; // 离线缓存的容器名，不是「每次改文件都要升」的版本号
```

只有当你想让所有已安装客户端一次性丢弃旧缓存时，才把这个名字改一下（例如 `cartlog-v20`）。

应用版本记录在 [CHANGELOG.md](CHANGELOG.md)（当前 1.1.0），与数据版本 `APP_VERSION = 5` 是两回事：后者只在 `localStorage` 结构与备份 JSON 格式变化时才升，升高了旧版应用会拒绝导入更新的备份。

## 自定义

- 平台、配件类型、区服及币种都在应用的「设置」页维护，不再需要改代码。
- 主题颜色在 `styles.css` 顶部的 CSS 变量与深色主题变量中统一调整。
- 修改图标后，重新用任意 SVG 转 PNG 工具生成 `icons/` 下的 PNG 文件。

## 隐私
